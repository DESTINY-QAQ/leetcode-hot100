1. 两数之和

在整数数组中找到两个和为目标值的元素，返回它们的数组下标；同一个元素不能重复使用。

数组哈希表一次遍历

查看 LeetCode 原题

我的代码记录

遍历数组时，用字典保存已经出现过的数字及其下标。对于当前数字，先查找它所需要的另一个数。

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)
        dict1 = dict()

        for i in range(n):
            if target - nums[i] in dict1:  # 查找的是键，而不是值
                return [i, dict1[target - nums[i]]]
            else:
                dict1[nums[i]] = i
最关键的顺序：必须先查询补数，再把当前元素放入字典。这样可以保证一个元素不会与自己匹配，同时又能正确处理 [3, 3] 这样的重复数字。

题目允许按任意顺序返回下标，所以这里返回 [当前下标, 已记录下标] 是正确的。

方法一：暴力枚举

枚举所有满足 i < j 的下标组合，直接判断两个元素之和是否等于目标值。

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)

        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]
时间复杂度 O(n²)最坏情况下需要检查约 n(n−1)/2 对元素。
空间复杂度 O(1)只使用循环下标，不需要额外数据结构。

问题不在于求出 target - nums[i]，而在于每次都要线性寻找这个补数，因此总时间达到平方级。

方法二解析：哈希表查补数

  1. 设当前数字为 x，那么需要寻找的补数是 target - x。
  2. 字典的键保存已经见过的数字，值保存对应下标。
  3. 如果补数已经是字典中的键，就找到了答案。
  4. 否则记录当前数字与下标，继续向右扫描。
平均时间复杂度 O(n)遍历一次数组，字典查询与插入平均为 O(1)。
空间复杂度 O(n)最坏情况下需要保存此前遍历过的元素。

整理后的提交版本

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}

        for i, num in enumerate(nums):
            complement = target - num

            if complement in seen:
                return [seen[complement], i]

            seen[num] = i

else 可以省略：找到答案时函数已经返回；没有找到时自然会执行后面的记录语句。名称 seen 也比 dict1 更能表达“已经见过的数字”。

示例推演与易错点

nums = [3, 2, 4]，target = 6

  1. 看到 3，需要补数 3；字典为空，记录 {3: 0}。
  2. 看到 2，需要补数 4；没有找到，记录 {3: 0, 2: 1}。
  3. 看到 4，需要补数 2；字典中已有下标 1，返回 [1, 2]。
  • 不要查字典的值：需要判断某个数字是否出现过，所以查询的是键；值只用于取得下标。
  • 不要先插入再查询：当 target == 2 * nums[i] 时，这会让当前元素错误地匹配自己。
  • 复杂度表述要准确：Python 字典操作是平均 O(1)，不是理论最坏情况下永远 O(1)。
